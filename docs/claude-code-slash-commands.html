什么是斜杠命令？

斜杠命令（Slash Commands）是在 Claude Code 交互式会话中使用的快捷命令。只需输入 /命令名 即可执行。例如：/help 显示帮助，/clear 清空对话。

🏠

基础命令

/help
基础

显示所有可用命令的帮助信息，当你忘记某个命令时非常有用。

💡 使用示例

> /help # 会显示所有可用命令列表及其简要说明
/clear
基础

清空当前对话历史，开始一个全新的对话。保留项目上下文，但清除之前的消息记录。

💡 使用场景

# 当对话太长想重新开始时 > /clear # 开始一个新的任务 > /clear > 请帮我创建一个新的组件...
⚠️ 清空后无法恢复历史对话
/compact
基础

压缩对话历史，减少 token 使用量。Claude 会总结之前的对话内容，保留关键信息。

💡 使用场景

# 对话很长时，压缩以节省 token > /compact # Claude 会总结之前的对话，保留关键上下文
💡 适合长对话后继续工作
/cost
基础

显示当前会话的 API 调用成本和 token 使用统计。

💡 输出示例

> /cost Token usage: - Input: 45,230 tokens - Output: 12,450 tokens - Total: 57,680 tokens - Cost: $0.35
/model
基础

查看或切换当前使用的模型。

💡 使用示例

# 查看当前模型 > /model Current model: claude-sonnet-4-20250514 # 切换模型 > /model opus Switched to claude-opus-4-20250514 # 可用模型 - sonnet (默认，平衡速度和质量) - opus (最强，适合复杂任务) - haiku (最快，适合简单任务)

会话管理

/resume
常用

恢复之前保存的会话，继续之前的工作。

💡 使用示例

# 恢复最近的会话 > /resume # 恢复特定会话（显示列表选择） > /resume # 命令行直接恢复 $ claude -r $ claude --resume "session-id"
✅ 会话会自动保存 💡 适合中断后继续工作
/save
常用

保存当前会话，以便之后恢复。

💡 使用示例

# 保存当前会话 > /save # 会话会被保存，可通过 /resume 恢复
/fork
进阶

创建当前会话的副本，可以在不同方向上继续探索，而不影响原会话。

💡 使用场景

# 想尝试不同方案时 > /fork # 创建分支后，可以尝试不同的实现方式 # 原会话保持不变
💡 适合对比不同方案
/export
基础

导出当前对话记录为文件。

💡 使用示例

# 导出对话记录 > /export # 会保存为 markdown 或 json 文件

Git 相关命令

/commit
常用

智能创建 Git 提交。Claude 会分析当前的改动，自动生成合适的提交信息。

💡 使用示例

# 创建提交（自动生成提交信息） > /commit # Claude 会： # 1. 运行 git status 查看改动 # 2. 运行 git diff 分析内容 # 3. 生成合适的提交信息 # 4. 执行 git commit
✅ 自动分析改动内容 ✅ 生成语义化提交信息
/pr
常用

创建 Pull Request。Claude 会分析当前分支的改动，生成 PR 标题和描述。

💡 使用示例

# 创建 PR > /pr # Claude 会： # 1. 分析当前分支的所有提交 # 2. 对比与目标分支的差异 # 3. 生成 PR 标题和描述 # 4. 使用 gh pr create 创建
✅ 需要 GitHub CLI (gh) 💡 自动生成变更摘要
/review
常用

审查当前 PR 或代码改动。Claude 会分析代码变更，检查潜在问题。

💡 使用示例

# 审查当前改动 > /review # 审查特定 PR > /review 123 # Claude 会检查： # - 代码质量 # - 潜在 bug # - 安全问题 # - 性能问题 # - 最佳实践
/init
常用

初始化项目的 CLAUDE.md 文件，为 Claude 提供项目上下文。

💡 使用示例

# 初始化项目配置 > /init # Claude 会： # 1. 分析项目结构 # 2. 识别技术栈 # 3. 生成 CLAUDE.md 文件 # 4. 包含项目说明、规范等
✅ 新项目第一步 💡 类似 .cursorrules
🔍

代码审查与质量

/security-review
安全

对当前改动进行安全审查，检查潜在的安全漏洞。

💡 检查内容

# 安全审查 > /security-review # 检查项目包括： # - SQL 注入风险 # - XSS 漏洞 # - 敏感信息泄露 # - 不安全的依赖 # - API 密钥暴露 # - 认证/授权问题
/health
质量

检查项目代码健康状况，运行类型检查、lint、测试等。

💡 使用示例

# 健康检查 > /health # 会运行： # - TypeScript 类型检查 # - ESLint 代码检查 # - 单元测试 # - 构建验证 # 并给出改进建议
/simplify
重构

简化最近修改的代码，提高可读性和可维护性。

💡 使用示例

# 简化代码 > /simplify # Claude 会： # - 检查重复代码 # - 简化复杂逻辑 # - 提取可复用部分 # - 改进命名

工作流命令

/loop
进阶

设置循环执行任务，可以定时运行某个命令或检查。

💡 使用示例

# 每 5 分钟检查一次部署状态 > /loop 5m /check-deploy # 每 10 分钟运行测试 > /loop 10m npm test # 停止循环 > /loop stop

参数格式

5m 5 分钟间隔
1h 1 小时间隔
30s 30 秒间隔
/ship
工作流

完整的发布工作流：检测基线分支、运行测试、审查代码、更新版本、生成 CHANGELOG。

💡 执行步骤

> /ship # 工作流步骤： 1. 检测并合并基线分支 2. 运行所有测试 3. 审查代码改动 4. 更新版本号 5. 更新 CHANGELOG 6. 创建提交和标签
/qa
测试

系统化测试 Web 应用，发现并修复 bug。

💡 使用示例

# 运行 QA 测试 > /qa # 会测试： # - 页面加载 # - 表单提交 # - 导航功能 # - 响应式布局 # - 错误处理
/investigate
调试

系统性调试，进行根因分析。

💡 调试流程

> /investigate # 四个阶段： 1. 调查 - 收集信息 2. 分析 - 找出模式 3. 假设 - 提出可能原因 4. 验证 - 确认根因

配置与设置

/config
配置

查看或修改 Claude Code 配置设置。

💡 使用示例

# 查看当前配置 > /config # 修改设置 > /config set model sonnet > /config set theme dark
/mcp
进阶

管理 MCP (Model Context Protocol) 服务器，扩展 Claude 的能力。

💡 使用示例

# 查看 MCP 服务器 > /mcp list # 添加 MCP 服务器 > /mcp add server-name # 测试 MCP 连接 > /mcp test server-name
/permissions
安全

管理 Claude Code 的权限设置。

💡 权限类型

# 查看权限设置 > /permissions # 权限类型： - 文件读取权限 - 文件写入权限 - 命令执行权限 - 网络请求权限
/statusline
界面

配置 Claude Code 的状态栏显示。

💡 使用示例

# 设置状态栏 > /statusline # 可以配置显示： # - 当前模型 # - Token 使用量 # - 工作目录 # - Git 状态
