基础命令

claude 最常用

启动 Claude Code 交互式会话。这是最基本也是最常用的命令，在项目目录下运行即可开始与 Claude 对话。

📋 语法

claude [选项]

💡 示例

# 在当前目录启动 Claude Code claude # 带提示词直接启动 claude "请帮我分析这个项目结构" # 指定工作目录 claude --cwd /path/to/project
✅ 首次运行会要求输入 API Key 💡 在项目根目录下启动效果最佳
claude --version 基础

查看当前安装的 Claude Code 版本号，用于确认安装成功或检查是否需要更新。

💡 示例

$ claude --version claude-code v1.0.0
✅ 安装后第一步验证
claude --help 基础

显示所有可用命令和选项的帮助信息，当你忘记某个命令时非常有用。

💡 示例

$ claude --help Usage: claude [options] [prompt] Options: -v, --version 显示版本号 -h, --help 显示帮助信息 --cwd 指定工作目录 ...
claude update 维护

更新 Claude Code 到最新版本。建议定期运行以获取新功能和 bug 修复。

💡 示例

# 更新到最新版本 claude update # 或者使用 npm 更新 npm update -g @anthropic-ai/claude-code
⚠️ 更新前建议保存当前工作

文件操作命令（交互式）

💡
重要说明

Claude Code 主要是交互式工具，大部分操作通过自然语言对话完成。以下是在对话中常用的文件操作提示词模板。

读取文件 提示词

让 Claude 读取并分析指定的文件内容。

💡 示例提示词

# 读取单个文件 请读取 index.html 的内容，告诉我这个页面做了什么 # 读取多个文件 请读取 src/ 目录下的所有 .js 文件 # 读取并解释 请读取 app.js，解释主要函数的作用
✅ Claude 会自动使用 Read 工具 💡 支持读取图片文件
创建文件 提示词

让 Claude 创建新的文件并写入内容。

💡 示例提示词

# 创建单个文件 请创建 styles.css 文件，包含基础的页面样式 # 创建多个文件 请创建以下文件： 1. index.html - 主页面 2. styles.css - 样式文件 3. app.js - 脚本文件 # 创建目录结构 请创建 src/components/ 目录，并添加 Header.jsx 文件
✅ 会自动创建不存在的目录 ⚠️ 会覆盖已存在的文件
修改文件 提示词

让 Claude 修改已存在的文件内容。

💡 示例提示词

# 简单修改 请修改 index.html，把标题改成"我的项目" # 添加内容 请在 app.js 中添加一个 debounce 函数 # 重构代码 请重构 app.js 中的 handleSubmit 函数，使其更简洁 # 批量修改 请修改所有 .jsx 文件，把 className="btn" 改成 className="button"
✅ 修改前会先读取文件 💡 使用 Edit 工具进行精确替换
查找文件 提示词

让 Claude 在项目中搜索文件或内容。

💡 示例提示词

# 按名称查找文件 请找到所有 .test.js 文件 # 按内容搜索 请在项目中搜索 "TODO" 注释 # 按模式查找 请找到所有以 "use" 开头的函数定义 # 复杂搜索 请在 src/ 目录下找到所有使用了 useState 的文件
✅ 使用 Glob 工具按模式匹配 ✅ 使用 Grep 工具按内容搜索
删除文件 提示词

让 Claude 删除指定的文件或目录。

💡 示例提示词

# 删除单个文件 请删除 temp.js 文件 # 删除目录 请删除 dist/ 目录 # 删除匹配的文件 请删除所有 .log 文件
⚠️ 删除操作不可恢复 🚨 执行前会要求确认

项目管理命令

项目分析 常用

让 Claude 分析整个项目的结构和技术栈。

💡 示例提示词

# 分析项目结构 请分析当前项目的结构，告诉我： 1. 这是什么类型的项目 2. 使用了什么技术栈 3. 主要文件和目录的作用 4. 项目的入口文件 # 技术栈识别 请识别这个项目使用的所有依赖库 # 架构分析 请分析这个项目的架构设计
Git 操作 常用

让 Claude 帮你执行 Git 命令管理版本。

💡 示例提示词

# 查看状态 请运行 git status，告诉我当前有哪些改动 # 提交代码 请帮我提交当前的改动，提交信息是"添加登录功能" # 创建分支 请创建一个新分支 feature/login # 查看 log 请显示最近 5 条 git 提交记录
✅ Claude 使用 Bash 工具执行命令 ⚠️ 危险操作会要求确认
依赖管理 常用

让 Claude 帮你管理项目依赖。

💡 示例提示词

# 安装依赖 请运行 npm install 安装项目依赖 # 添加依赖 请安装 axios 库 # 添加开发依赖 请安装 typescript 作为开发依赖 # 查看过期依赖 请检查哪些依赖需要更新
运行脚本 常用

让 Claude 运行 package.json 中定义的脚本或自定义命令。

💡 示例提示词

# 启动开发服务器 请运行 npm run dev # 构建项目 请运行构建命令 # 运行测试 请运行所有测试 # 执行自定义命令 请执行 node scripts/migrate.js
💡 长时间运行的命令可在后台执行

配置与设置

API Key 配置 首次使用

配置 Anthropic API Key，首次使用时必需。

💡 配置方式

# 方式 1：首次启动时自动提示输入 claude # 会提示：Enter your Anthropic API key: # 方式 2：设置环境变量 export ANTHROPIC_API_KEY="your-api-key-here" # 方式 3：在 .env 文件中配置 ANTHROPIC_API_KEY=your-api-key-here
⚠️ API Key 不要分享给他人 💡 可在 https://console.anthropic.com 获取
CLAUDE.md 配置 进阶

在项目根目录创建 CLAUDE.md 文件，为 Claude 提供项目特定的指令和上下文。

💡 CLAUDE.md 示例

# 项目：My App ## 技术栈 - React 18 + TypeScript - Tailwind CSS - Vite ## 代码规范 - 使用函数组件和 Hooks - 组件文件使用 PascalCase 命名 - 样式使用 Tailwind 类名 ## 注意事项 - 所有 API 调用都在 src/services/ 目录 - 测试文件与源文件同目录
✅ Claude 启动时会自动读取 💡 类似 .cursorrules 文件
权限与安全 进阶

Claude Code 有多层安全机制保护你的系统。

权限类型 说明
读取文件 默认允许读取项目目录内的文件
写入文件 修改文件前会显示 diff 供确认
执行命令 危险命令（删除、强制推送等）需要确认
网络请求 默认禁止，需要明确授权

高效使用技巧

明确指定文件路径 效率
❌ 模糊 ✅ 明确
"改一下那个文件" "修改 src/components/Header.jsx"
"把样式改了" "修改 styles/main.css 的第 15-20 行"
分步而非一次完成 质量

❌ 不推荐：一次性要求太多

请帮我创建一个完整的用户管理页面， 包含列表、搜索、新增、编辑、删除功能， 还要有表单验证和错误提示...

✅ 推荐：分步进行

# 第一步 请创建用户列表页面的基础结构 # 第二步 请添加搜索功能 # 第三步 请添加新增用户的弹窗
提供上下文信息 质量

💡 好的提示词结构

背景：这是一个 React + TypeScript 项目 目标：添加一个用户头像组件 要求： 1. 支持圆形和方形两种样式 2. 默认显示用户名首字母 3. 支持传入图片 URL 文件位置：src/components/Avatar.tsx 样式方案：使用 Tailwind CSS
利用 Git 保护代码 安全

在让 Claude 修改代码前，先提交当前状态，方便回退。

💡 推荐工作流

# 修改前 git add . && git commit -m "保存当前状态" # 让 Claude 修改代码 "请重构 app.js 中的登录逻辑" # 检查改动 git diff # 如果满意，提交 git add . && git commit -m "重构登录逻辑" # 如果不满意，回退 git checkout .
让 Claude 解释代码 学习

不仅是让 Claude 写代码，也要让它解释代码，这样你能学到更多。

💡 示例提示词

# 解释某段代码 请解释 src/utils/date.js 中 format 函数的实现原理 # 解释项目架构 请解释这个项目的数据流向 # 解释某个概念 请解释 React 中 useEffect 的依赖数组是如何工作的
处理报错信息 调试

遇到报错时，提供完整的信息给 Claude。

💡 报错处理模板

我遇到一个错误，请帮我分析： 错误信息： [粘贴完整的错误堆栈] 我正在做什么： [描述你的操作] 期望结果： [描述你期望发生什么] 实际结果： [描述实际发生了什么] 相关代码文件： [告诉 Claude 查看哪些文件]

常见问题

Q: Claude Code 能操作项目外的文件吗？

A: 默认情况下，Claude Code 只能操作当前工作目录及其子目录下的文件。如果需要访问其他目录，需要明确指定完整路径。

Q: 如何让 Claude Code 使用特定的模型？

A: Claude Code 会自动使用最适合的模型。目前默认使用 Claude 3.5 Sonnet，平衡了速度和质量。可通过配置或对话中指定需求来调整。

Q: Claude Code 会自动保存我的代码吗？

A: Claude Code 修改文件时会直接保存。建议使用 Git 版本控制，这样可以随时查看和回退改动。

Q: 对话历史会保存吗？

A: 当前会话中的对话会保持在上下文中。但每次新启动 Claude Code 都是新的会话，之前的对话不会自动恢复。建议重要的决策和代码用 Git 或文档保存。

Q: 如何处理敏感信息？

A: 不要在对话中分享敏感信息（API Key、密码、密钥等）。建议使用环境变量或专门的配置文件管理敏感信息，并确保这些文件在 .gitignore 中。

Q: 遇到 "permission denied" 错误怎么办？

A: 这通常是因为 Claude Code 没有权限操作某个文件或目录。检查文件权限，或尝试使用 sudo 运行（不推荐，仅作为最后手段）。

🎯 记住三个核心原则

1. 明确具体 - 指定文件路径、行号、具体需求
2. 分步进行 - 一次一个任务，完成验证后再继续
3. 持续验证 - 每次改动都要检查，用 Git 保护代码
