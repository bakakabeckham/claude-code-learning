A

Claude Code CLI 是什么

🤔 先问一个问题：你平时怎么用 AI 写代码？

大多数人可能是这样：打开网页版的 ChatGPT 或 Claude，问它"帮我写一个登录页面"，然后复制代码到编辑器里。

这种方式的问题：

  • 你得手动复制粘贴代码
  • 它看不到你项目的其他文件
  • 它不知道你的项目结构
  • 报错了你得自己把错误信息复制过去
  • 改一个文件可能影响其他文件，它不知道
💡
Claude Code CLI 是什么？

Claude Code CLI 是一个在你的终端（命令行）里运行的 AI 编程助手，它可以直接操作你电脑上的文件，读取你的项目代码，帮你写代码、改代码、修 bug，而且它会"看到"你整个项目。

🔄 Claude Code CLI 和其他工具的区别

对比维度 网页版 AI IDE 插件 Claude Code CLI
能看到项目吗 ❌ 只能看到你粘贴的内容 ⚠️ 能看到当前文件 ✅ 能看到整个项目
能直接改文件吗 ❌ 需要你手动复制 ⚠️ 部分可以 ✅ 直接读写文件
能执行命令吗 ❌ 完全不能 ❌ 不能 ✅ 可以运行终端命令
能分析报错吗 ⚠️ 需要你粘贴错误信息 ⚠️ 需要手动操作 ✅ 自动读取并分析
学习成本 低，打开网页就能用 中等，需要安装配置 中等，需要学基础命令

🎯 Claude Code CLI 的定位

把 Claude Code CLI 想象成一个"坐在你电脑前的程序员伙伴"：

  • 它能"看"到你项目里的所有文件
  • 它能"动手"创建、修改、删除文件
  • 它能"执行"命令（比如运行代码、安装依赖）
  • 它能"理解"报错信息并给出修复方案
  • 它能"规划"任务，帮你拆解工作
✅
适合这些人
  • 想快速上手做项目的编程新手
  • 能接受命令行操作的人
  • 想系统化开发一个完整项目的人
  • 希望 AI 能"看到"整个项目上下文的人
  • 愿意一步步学习如何和 AI 协作的人
⚠️
可能不适合这些人
  • 完全不想碰命令行的人
  • 期望 AI 自动完成一切、自己不用动脑的人
  • 只想要代码片段，不想系统开发的人
  • 对"让 AI 操作我电脑上的文件"有顾虑的人
🚨
新手必须建立的正确预期
  • 它不是魔法：它也会犯错，也会写 bug，你仍然需要检查
  • 它需要你的引导：你描述得越清楚，它做得越好
  • 它不能替代你的思考：架构决策、需求理解还得靠你
  • 它是一次性收费的助手：每次对话都有 token 限制，不要指望它能记住所有历史
  • 最好分段工作：一个任务做完再开下一个，不要一次塞太多需求
B

新手必须掌握的基本操作

📦 安装前准备

在安装 Claude Code CLI 之前，你需要确保：

  • 一台电脑：Windows、Mac 或 Linux 都可以
  • 终端/命令行工具：Mac 用 Terminal，Windows 用 PowerShell 或 Git Bash
  • Node.js 环境：建议安装 Node.js 18 或更高版本
  • Anthropic API Key：需要一个有效的 API 密钥
1

安装 Node.js（如果还没有）

访问 nodejs.org 下载并安装 LTS 版本。安装完成后，在终端输入：

终端命令 node --version

如果显示版本号（如 v18.17.0），说明安装成功。

2

安装 Claude Code CLI

在终端中运行：

终端命令 npm install -g @anthropic-ai/claude-code

这个过程可能需要几分钟，取决于你的网络速度。

3

验证安装

安装完成后，输入：

终端命令 claude --version

如果显示版本号，说明安装成功！

4

启动 Claude Code

在你想要工作的项目目录下，输入：

终端命令 claude

首次启动会让你输入 API Key，按提示操作即可。

🎯 核心操作：让 Claude Code 干活

启动后，你会看到一个聊天界面。这里的关键是：你用自然语言描述任务，它来执行。

📁 操作 1：让它查看项目结构

目的：让 Claude Code 了解你的项目长什么样。

示例提示词 请看一下当前项目的文件结构，告诉我这是什么类型的项目？

它会读取当前目录下的文件，给你一个概述。

📄 操作 2：让它读取特定文件

目的：让 Claude Code 看某个文件的内容。

示例提示词 请读取 index.html 的内容，告诉我这个页面做了什么

✨ 操作 3：让它创建新文件

目的：让 Claude Code 生成新的代码文件。

示例提示词 请创建一个 styles.css 文件，包含基础的页面样式

它会在当前目录下创建这个文件。

✏️ 操作 4：让它修改已有代码

目的：让 Claude Code 改进现有的文件。

示例提示词 请修改 index.html，把标题改成"我的待办清单"，并添加一个输入框

🐛 操作 5：让它分析报错

目的：遇到错误时，让 Claude Code 帮你分析。

示例提示词 我运行了 npm start，但是报错了，错误信息是： Error: Cannot find module 'express' 请帮我分析问题并修复

它会分析原因，并可能帮你安装缺失的依赖。

📊 操作 6：让它帮你拆任务

目的：不知道从哪开始时，让它帮你规划。

示例提示词 我想做一个待办清单应用，请帮我： 1. 列出需要完成的功能清单 2. 给出推荐的文件结构 3. 按优先级排序开发顺序

⚡ 操作 7：配合终端使用

Claude Code 可以直接执行终端命令，你只需要告诉它：

示例提示词 请帮我执行 npm install 来安装依赖
⚠️
安全提示

Claude Code 执行命令前会询问你确认。对于删除文件、修改系统设置等敏感操作，请仔细检查。

🪜 操作 8：逐步开发，不要一次全生成

这是新手最容易犯的错误：想一次性让 AI 生成整个项目。

❌ 错误示范

"帮我生成一个完整的待办清单应用，要有添加、删除、编辑功能，数据要保存到本地，界面要好看..."

问题：输出质量差、容易出错、难以调试

✅ 正确示范

"先帮我创建一个最基础的 HTML 页面，只有一个标题和一个输入框"

优点：可控、可验证、易于迭代

🚫 常见错误操作

  1. 不指定文件位置：说"创建一个文件"，没说创建在哪里、叫什么名字
  2. 需求描述模糊：说"做一个好看的页面"，没有具体说明"好看"是什么样
  3. 忽略项目结构：在错误的目录下启动 Claude Code
  4. 一次塞太多需求：把所有功能一次说完，导致输出质量下降
  5. 不看就接受：AI 改完代码不检查，直接运行
  6. 不会用 git：改坏了没法回退
💡
新手避坑建议
  • 每次只做一件事：生成一个文件、修改一个功能
  • 先跑起来再优化：不要追求完美，先让东西能工作
  • 用 git 管理版本：每次 Claude Code 改完后提交一次
  • 保持对话简洁：一个任务完成后，可以开新对话
  • 学会看代码：不要完全不看 AI 写的代码

从 0 到 1 做项目必须具备的能力地图

借助 Claude Code 做项目，不是"让 AI 干活"这么简单。作为一个新手，你需要建立以下 10 项核心能力：

🎯

1. 需求理解能力

是什么：能清晰描述"我要做什么"的能力

  • 没有它：AI 不知道你要什么
  • Claude Code 能帮你：梳理需求、提问澄清
  • 练习方法：试着写"产品需求文档"
📦

2. 任务拆解能力

是什么：把大目标拆成小任务的能力

  • 没有它：不知道从哪开始
  • Claude Code 能帮你：生成任务清单
  • 练习方法：用 AI 帮你拆，然后自己验证
💬

3. 提示词表达能力

是什么：用 AI 能理解的方式描述任务

  • 没有它：AI 输出质量差
  • Claude Code 能帮你：提供模板参考
  • 练习方法：对比好提示词和差提示词
📂

4. 项目结构阅读能力

是什么：理解项目的文件组织方式

  • 没有它：不知道改哪个文件
  • Claude Code 能帮你：解释项目结构
  • 练习方法：让 AI 带你看懂几个开源项目
✏️

5. 代码修改与验证能力

是什么：改了代码能验证改对了

  • 没有它：改坏了不知道
  • Claude Code 能帮你：生成测试代码
  • 练习方法：每次改完立即运行验证
🔍

6. 报错理解能力

是什么：看到错误信息知道大概出了什么问题

  • 没有它：一报错就卡住
  • Claude Code 能帮你：解释错误原因
  • 练习方法：把错误信息交给 AI 解释
🔧

7. 调试能力

是什么：找到问题根源并修复

  • 没有它：不知道问题出在哪
  • Claude Code 能帮你：分析代码逻辑
  • 练习方法：故意制造 bug 让 AI 帮你找
✅

8. 测试与验收能力

是什么：判断功能是否完成、是否正确

  • 没有它：不知道什么时候算做完
  • Claude Code 能帮你：生成测试清单
  • 练习方法：自己写验收标准
🔄

9. 迭代优化能力

是什么：在现有基础上逐步改进

  • 没有它：改着改着就乱了
  • Claude Code 能帮你：建议优化方案
  • 练习方法：一次只改一个地方
🤝

10. 与 AI 协作的能力

是什么：知道什么该问 AI，什么该自己判断

  • 没有它：要么过度依赖，要么不会用
  • Claude Code 能帮你：给建议和提示
  • 练习方法：项目做完后复盘
📌
能力培养建议

不要指望一次学会所有能力。建议：每做一个项目，重点练习 2-3 项能力。能力是实战出来的，不是看会的。

实战项目：个人待办清单

🎯 为什么选择"待办清单"作为新手项目？

在所有练习项目中，待办清单（Todo List）是最适合新手的第一项目，原因如下：

  • 功能直观：你每天都会用到，很清楚它该是什么样
  • 范围可控：核心功能就 3 个（添加、完成、删除），不会失控
  • 可扩展：做完基础版，可以逐步加编辑、分类、优先级等功能
  • 技术覆盖全面：HTML 结构、CSS 样式、JavaScript 交互都能练到
  • 即时反馈：每做一个功能，立即能看到效果
  • 难度适中：不会太简单没学到东西，也不会太难打击信心

📋 最终成品预览

完成后的待办清单应用包含：

  • 一个输入框，用于添加新任务
  • 一个任务列表，显示所有待办事项
  • 每个任务可以标记"完成"或"删除"
  • 数据保存在浏览器中，刷新不丢失
  • 简洁美观的界面

技术栈：纯 HTML + CSS + JavaScript（不依赖框架）

📍 第 1 步：明确需求

❓
先问自己几个问题
  • 这个应用给谁用？→ 我自己用
  • 核心功能是什么？→ 添加任务、标记完成、删除任务
  • 需要登录吗？→ 不需要
  • 数据要保存吗？→ 保存到浏览器就行
  • 要多好看？→ 简洁能用就行

什么叫需求范围？就是界定"做什么"和"不做什么"。

❌ 错误示范

"我要做一个待办清单，要有登录注册、云同步、分类标签、优先级、提醒功能、日历视图..."

问题：范围太大，新手做不完

✅ 正确示范

"我要做一个简单的待办清单，能添加、完成、删除任务，数据存在浏览器里，界面简洁就行"

优点：范围清晰，容易完成

Claude Code 提示词示例 我想做一个简单的待办清单网页应用，需求如下： 1. 用户可以输入任务名称，添加到列表 2. 用户可以点击任务标记为"已完成" 3. 用户可以删除任务 4. 数据保存在浏览器本地存储中 5. 界面简洁美观即可 请帮我确认一下这个需求是否清晰，有没有遗漏的要点？

📍 第 2 步：拆解任务

把"做待办清单"这个大目标，拆成具体的小任务。

Claude Code 提示词示例 基于上面的需求，请帮我拆解开发任务： 1. 按优先级排列任务顺序 2. 每个任务说明需要创建什么文件 3. 估计每个任务的复杂度（简单/中等/复杂）

Claude Code 可能输出的任务清单：

  1. 创建项目目录结构（简单）
  2. 编写基础 HTML 页面（简单）
  3. 添加基础 CSS 样式（简单）
  4. 实现添加任务功能（中等）
  5. 实现显示任务列表（中等）
  6. 实现标记完成功能（中等）
  7. 实现删除任务功能（中等）
  8. 实现本地存储（中等）
  9. 界面美化优化（简单）

📍 第 3 步：初始化项目

创建项目的基础结构。

Claude Code 提示词示例 请帮我创建一个 todo-app 文件夹，里面包含： - index.html（主页面） - styles.css（样式文件） - app.js（脚本文件） 先只创建空的文件结构，暂时不写内容。
⚠️
易错点

不要让 AI 一次性生成所有代码。先建立结构，再逐步填充内容。

📍 第 4 步：生成 MVP（最小可运行版本）

💡
什么是 MVP？

MVP = Minimum Viable Product（最小可行产品）。意思是：用最少的代码，先让东西能跑起来。

为什么要先做 MVP？

  • 快速验证想法对不对
  • 尽早发现重大问题
  • 建立信心和成就感
  • 便于后续增量开发
Claude Code 提示词示例 现在请帮我完成一个最基础的版本： 1. index.html：只包含一个标题、一个输入框、一个添加按钮、一个空的任务列表区域 2. styles.css：只添加最基础的样式，让页面能看就行 3. app.js：暂时留空 要求：代码尽量简单，先让页面能显示出来。

验证方式：用浏览器打开 index.html，看页面是否正常显示。

📍 第 5 步：逐步添加功能

现在基础有了，开始一项项加功能。注意：每次只加一个功能。

功能 1：添加任务

Claude Code 提示词 现在实现"添加任务"功能： 1. 用户在输入框输入任务名称 2. 点击"添加"按钮后，任务出现在列表中 3. 输入框清空，可以继续输入 4. 暂时不需要保存数据，刷新就消失也没关系 请在 app.js 中添加相应代码。

功能 2：标记完成

Claude Code 提示词 现在实现"标记完成"功能： 1. 每个任务旁边有一个复选框 2. 点击复选框，任务文字变成删除线样式 3. 再次点击可以取消完成状态

功能 3：删除任务

Claude Code 提示词 现在实现"删除任务"功能： 1. 每个任务旁边有一个删除按钮 2. 点击后，该任务从列表中移除

功能 4：本地存储

Claude Code 提示词 现在实现数据持久化： 1. 使用 localStorage 保存任务数据 2. 页面加载时，自动读取并显示已保存的任务 3. 添加、完成、删除操作后都要更新存储

📍 第 6 步：运行、报错、修复

开发过程中遇到报错是正常的，关键是要学会如何处理。

报错时该怎么办？

  1. 不要慌：报错信息是你解决问题的线索
  2. 读取错误信息：看错误类型、出错的文件和行号
  3. 复制完整错误：把完整的错误信息交给 Claude Code
  4. 描述上下文：告诉 AI 你在做什么操作时出现的错误
Claude Code 报错分析提示词 我在测试添加任务功能时遇到了错误，请帮我分析： 错误信息： Uncaught TypeError: Cannot read property 'addEventListener' of null at app.js:15 我正在尝试点击添加按钮，但是没有反应。 请： 1. 解释这个错误是什么意思 2. 分析可能的原因 3. 给出修复方案
💡
验证修复是否有效

修复后，按照以下步骤验证：

  • 刷新页面
  • 重复之前报错的操作
  • 如果不再报错，说明修复成功
  • 如果还有问题，继续把新错误信息交给 AI

📍 第 7 步：优化结构与体验

功能完成后，可以考虑优化。

❓
什么时候该优化？
  • 所有核心功能都已完成
  • 功能测试都通过
  • 有明确可改进的地方
Claude Code 优化提示词 现在功能已经完成了，请帮我优化： 1. 视觉优化：让界面看起来更现代、更美观 2. 交互优化：添加一些动画效果，比如添加任务时的淡入效果 3. 代码优化：检查代码是否有重复或可以简化的地方 请一步一步来，每次改动后让我确认。

📍 第 8 步：测试与验收

怎么判断"项目完成了"？需要系统测试。

Claude Code 测试清单提示词 请帮我生成一个测试检查清单，用于验证这个待办清单应用是否完成。 格式要求： 1. 测试项 2. 预期结果 3. 测试步骤

示例测试清单：

测试项 测试步骤 预期结果
添加任务 输入"买菜"，点击添加 列表中出现"买菜"
标记完成 点击任务前的复选框 任务显示删除线
删除任务 点击删除按钮 任务从列表消失
数据持久化 添加任务后刷新页面 任务仍然存在

📍 第 9 步：继续迭代

基础版本完成后，可以继续添加新功能。

⚠️
迭代开发的原则
  • 一次只加一个功能
  • 每个功能都要测试通过后再加下一个
  • 新功能不能破坏已有功能

小白最常见 FAQ

我不会写代码，能不能用 Claude Code 做项目？ +

可以，但有条件。

Claude Code 能帮你写代码，但你仍然需要：

  • 能描述清楚你想要什么
  • 能判断 AI 做得对不对
  • 遇到问题能继续追问

建议：边做项目边学习基础概念，不要期望零基础就能做出复杂项目。

我该一次性让它生成全部内容吗？ +

绝对不要！

一次性生成全部内容的问题：

  • 代码量大，出错概率高
  • 出错后难以定位问题
  • 难以理解和维护

正确做法：小步快跑，一次做一个功能，做完测试通过再做下一个。

为什么它生成的代码和我想的不一样？ +

通常是描述不够具体。

AI 只能根据你的描述来生成，如果描述模糊，它就会"猜"你的意图。

解决方法：

  • 提供更详细的需求描述
  • 给出参考示例或截图
  • 让它先解释理解，确认无误后再生成
我看不懂报错怎么办？ +

没关系，这正是 Claude Code 的强项。

操作步骤：

  1. 复制完整的错误信息
  2. 告诉 AI 你在做什么操作时出错
  3. 让 AI 解释错误原因并提供修复方案

久而久之，你会学会看懂常见错误。

我不知道下一步做什么怎么办？ +

问 Claude Code！

示例提示词：

我已经完成了 [当前状态]，请帮我： 1. 检查是否有遗漏的功能 2. 建议下一步可以做什么 3. 按优先级排序
我怎么判断 AI 写得对不对？ +

三个方法：

  1. 运行测试：功能能不能正常工作
  2. 代码审查：让 AI 解释代码逻辑，看是否合理
  3. 对比需求：是否满足你最初的需求

记住：AI 也会犯错，不要盲目信任，要验证。

我怎么避免被 AI 带偏？ +

关键原则：你做决策，AI 执行。

  • 先想清楚要什么，再问 AI
  • 让 AI 解释它的方案，而不是直接接受
  • 对重要决策，让 AI 给出多个方案供选择
  • 保持对项目的掌控感，AI 是助手不是老板
我该先学命令，还是先做项目？ +

边做边学效果最好。

建议路径：

  1. 先掌握最基本的 3-5 个操作
  2. 马上开始做一个简单项目
  3. 遇到需要的新命令时现学
  4. 在实践中巩固

单纯学命令很枯燥，没有上下文很难记住。

做项目时我该怎么和 Claude Code 分工？ +

分工原则：

你负责 Claude Code 负责
确定要做什么 建议实现方案
验收功能是否正确 编写具体代码
做架构决策 分析技术选项
判断优先级 拆解任务清单
提出问题 解释原因

核心：你思考，它执行。
